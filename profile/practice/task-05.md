## Часть А. Сетевой слой (8 баллов)

### 1. API и разрешение

- выберите **публичный API без ключа и регистрации**. Подойдут, например:
  - `https://jsonplaceholder.typicode.com/` — тестовые посты, пользователи, фото;
  - `https://api.open-meteo.com/` — погода по координатам;
  - `https://dog.ceo/api/` — случайная картинка собаки;
  - `https://picsum.photos/` — картинки по URL.
- в `AndroidManifest.xml` добавлено разрешение `INTERNET`;
- используется `https://`, без `usesCleartextTraffic`.

### 2. Retrofit и DTO

- создан интерфейс сервиса с одним `suspend`-методом, возвращающим DTO;
- DTO — `data class` с `@Serializable`;
- подключён конвертер Kotlin Serialization (или конвертер из шаблона курса);
- Retrofit работает поверх **OkHttp**: `OkHttpClient` создаётся в Hilt-модуле
  (таймауты и логирование — по желанию);
- базовая URL и сервис создаются один раз и предоставляются через **Hilt-модуль**;
- в коде нет ручной сборки JSON строками.

Пример формы (имена и поля — под ваш API):

```kotlin
@Serializable
data class PostDto(val id: Int, val title: String, val body: String)

interface ApiService {
    @GET("posts/1")
    suspend fun getPost(): PostDto
}
```

### 3. Репозиторий и ViewModel

- репозиторий вызывает сервис и возвращает доменную модель (или `Result`);
- ViewModel запускает запрос в `viewModelScope`;
- состояние экрана описано явно:

```kotlin
sealed interface UiState {
    data object Loading : UiState
    data class Success(val items: List<Post>) : UiState
    data class Error(val message: String) : UiState
    data object Empty : UiState
}
```

- UI получает готовое состояние из ViewModel и не вызывает Retrofit напрямую.

### 4. Экран и состояния

На экране видны все четыре состояния:

- **Loading** — индикатор загрузки;
- **Success** — данные (список или карточка);
- **Empty** — понятная надпись, если API вернул пустой список;
- **Error** — текст ошибки и кнопка **«Повторить»**, которая повторяет запрос.

Приложение не падает при выключенном интернете и при ошибке сервера.

### 5. Картинка через Coil

- на экране есть хотя бы одно изображение, загруженное по URL через `AsyncImage` (Coil);
- пока картинка грузится, виден placeholder или индикатор;
- битая ссылка не роняет экран.

### 6. Корутины и потоки

- сетевой вызов выполняется в корутине, не в main-потоке;
- отмена экрана отменяет запрос (`viewModelScope`);
- нет `GlobalScope` и `runBlocking`;
- ошибки ловятся (`try/catch` или `Result`), а не проглатываются.

## Частые ошибки

- забыли `INTERNET` в манифесте — запрос падает с `SecurityException`;
- API на `http://` без `usesCleartextTraffic`;
- Retrofit-вызов на main-потоке;
- нет обработки ошибок: при выключенном интернете приложение падает;
- `UiState` не описан, UI сам решает, что показать;
- кнопка «Повторить» есть, но ничего не перезапрашивает;
- Coil подключён, но картинка грузится без placeholder и «прыгает»;
- базовая URL захардкожена в composable, а не в Hilt-модуле.

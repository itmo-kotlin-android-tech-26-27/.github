## Часть А. Сквозной сценарий (8 баллов)

### 1. Полный сценарий

- путь **старт → действие → результат → возврат на старт** проходится без тупиков;
- все заявленные экраны достижимы;
- нет экранов, на которые можно попасть, но нельзя вернуться;
- нет «болтающихся» кнопок, которые ничего не делают.

### 2. Данные идут через слои

- UI не содержит демо-данных и не создаёт репозитории;
- все данные приходят из ViewModel;
- Room используется для основной сущности, DataStore — для настройки;
- сеть используется там, где заявлена, и не ломает офлайн-сценарий;
- после перезапуска данные и настройка на месте.

### 3. Состояния

На каждом экране, где данные могут отсутствовать или грузиться, есть:

- **Loading** — индикатор;
- **Empty** — текст и действие;
- **Error** — сообщение и повтор/возврат;
- **Success** — нормальный контент.

Не должно быть пустого белого экрана ни в одной из этих ситуаций.

### 4. Ввод и ошибки

- пустой и некорректный ввод не приводит к падению;
- кнопка блокируется или показывает сообщение;
- ошибки Room/сети показываются пользователю, а не только в Logcat;
- повтор действия после ошибки работает.

### 5. Навигация и поворот

- back с результата возвращает на предыдущий шаг, не создаёт дубликатов;
- поворот экрана не сбрасывает ввод, выбранный элемент и прогресс;
- deep link/аргументы не теряются при повороте.

### 6. Три проверочных прогона

Приложение не падает и ведёт себя осмысленно в трёх сценариях:

1. **Happy path** — все данные есть, сценарий проходит до конца.
2. **Пусто** — база очищена/API вернул пусто; видно пустое состояние и способ вернуться.
3. **Ошибка** — авиарежим или недоступный API; видно сообщение и повтор.

Плюс сборка `./gradlew :app:assembleDebug` без ошибок.

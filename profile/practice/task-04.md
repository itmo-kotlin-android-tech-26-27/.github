## Часть А. Room + DataStore (8 баллов)

### 1. Сущность и таблица

- одна основная сущность проекта помечена `@Entity`;
- у неё есть первичный ключ (`@PrimaryKey(autoGenerate = true)` или естественный ключ);
- минимум три поля, включая хотя бы одно не-строковое (число, дата, boolean, enum);
- имя таблицы задано явно.

### 2. DAO

- интерфейс помечен `@Dao`;
- есть методы:
  - `Flow<List<Entity>>` для чтения списка;
  - `suspend fun insert(...)`;
  - `suspend fun update(...)` или `suspend fun upsert(...)`;
  - `suspend fun delete(...)` или `deleteById(...)`;
- запросы написаны на SQL, без ручной сборки строк из пользовательского ввода.

### 3. База данных

- класс помечен `@Database(entities = [...], version = 1, exportSchema = false)`;
- база создаётся через `Room.databaseBuilder(...)`;
- база и DAO предоставляются через **Hilt-модуль**;
- база не создаётся в composable-функции и не хранится в глобальном `object`.

### 4. Репозиторий и ViewModel

- репозиторий скрывает DAO за интерфейсом;
- ViewModel получает репозиторий через Hilt;
- список в UI читается из `Flow`/`StateFlow`;
- после `insert`/`delete` UI обновляется **без ручного перезапуска экрана**.

### 5. Сохранение между запусками

- добавленная запись видна после полного закрытия и повторного открытия приложения;
- удаление записи сохраняется;
- если база пустая — показывается пустое состояние с кнопкой добавления;
- при первом запуске база заполняется демо-данными (3–5 записей), чтобы сценарий можно было
  пройти сразу.

### 6. DataStore

- подключён `Preferences DataStore`;
- хранится **одна настройка** проекта: например, имя пользователя, тема, порядок сортировки,
  выбранный режим;
- чтение — через `Flow`, запись — через `suspend`-функцию;
- настройка реально влияет на UI (сортировка, тема, приветствие и т.п.);
- настройка сохраняется после перезапуска.

### 7. Потоки и ошибки

- нет блокирующих операций с базой в main-потоке;
- ошибки чтения/записи не приводят к падению: показывается сообщение или пустое состояние;
- `Flow` собирается с учётом жизненного цикла (`collectAsStateWithLifecycle`).

## Частые ошибки

- база или репозиторий создаются в composable-функции;
- DAO возвращает `List`, а не `Flow`, и UI не обновляется после вставки;
- `Room.databaseBuilder` вызывается на main-потоке;
- `allowMainThreadQueries()` вместо `suspend`/`Flow`;
- DataStore читается через `runBlocking`;
- настройка сохраняется, но ни на что не влияет;
- нет демо-сида: после установки пустой экран, сценарий не пройти;
- `exportSchema = true` без папки `schemas/` — сборка падает.
